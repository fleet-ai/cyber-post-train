# Operational lessons

This is the routing index for experiment failures that changed how this
repository operates. It is not a live job-status page and it does not replace
the linked receipts. Exact run identities and outcomes belong in sanitized,
immutable evidence; reusable checks belong in code and regression tests.

Last reconciled against `main` commit
`6ba1042dfc0f8f8a64d0ad4d02a21adfd590d91e` on 2026-09-21.

## What “closed” means

A repeated failure class is closed only when all four durable layers exist:

1. a sanitized receipt or immutable config records what actually happened;
2. code rejects or correctly handles the failure at the narrowest deterministic
   boundary;
3. a regression test proves that boundary; and
4. this index or the focused runbook explains the reusable rule.

If the boundary is owned by an external service, local code must fail closed at
preview or preflight and the exact upstream repair must be linked. A successful
test proves only its stated boundary; it does not prove a model trained, a
checkpoint reloaded, or an evaluation produced a valid capability result.

Status terms below are deliberate:

- **enforced on main** — code and a focused regression are in the main branch;
- **repair in review** — the incident is proven and an exact repair commit is
  linked, but main must not be treated as enforcing it yet;
- **historical context** — evidence explains an incident but is not itself an
  executable guard.

## Closed lessons on main

| Failure boundary | Reusable rule | Durable anchors |
|---|---|---|
| Root failed-job alert setting | A request flag is not enough. Before create, require the rendered root `Job` or `RayJob` annotation `fleet.ai/failure-alerts: "off"`; a Pod-template annotation does not qualify. | **Enforced on main:** [`cyber_post_train/jobs.py`](../cyber_post_train/jobs.py), [`tests/test_generic_jobs.py`](../tests/test_generic_jobs.py), and the repository-wide manifest census in [`tests/test_cluster_failure_alert_opt_out.py`](../tests/test_cluster_failure_alert_opt_out.py). Procedure and limits: [`CLUSTER_ALERTS_AND_INFERENCE_SERVING.md`](CLUSTER_ALERTS_AND_INFERENCE_SERVING.md). |
| Jobs API release | A successful delete is exactly an empty HTTP 204. Do not parse JSON, and never replay an uncertain delete after a transport error; reconcile API and Kubernetes identity first. | **Enforced on main:** `Jobs.delete` in [`cyber_post_train/jobs.py`](../cyber_post_train/jobs.py) and `test_delete_accepts_exact_empty_204_and_never_parses_json` in [`tests/test_generic_jobs.py`](../tests/test_generic_jobs.py). |
| SFT per-token output retention | Scalar SFT must call native forward/backward with `return_per_token_outputs=False`. Retaining token-level outputs across steps can create monotonic GPU-memory growth and a delayed OOM even though early steps are finite. | **Enforced on main:** [`training/sft_runtime.py`](../training/sft_runtime.py) and [`tests/test_sft_runtime.py`](../tests/test_sft_runtime.py). The affected and preserved checkpoint states are recorded in [`configs/evaluation/qwen38-checkpoint-eval-ledger-v1.json`](../configs/evaluation/qwen38-checkpoint-eval-ledger-v1.json). |
| Qwen Megatron-LoRA checkpoint recovery | A TP8 Megatron checkpoint is not an FSDP or generic PEFT checkpoint. Seal its exact all-rank layout under the Qwen Megatron schema, then require a native all-rank reload before resume or promotion. | **Enforced on main:** [`training/checkpoints.py`](../training/checkpoints.py), [`training/recovery.py`](../training/recovery.py), [`tests/test_checkpoints.py`](../tests/test_checkpoints.py), and [`tests/test_recovery.py`](../tests/test_recovery.py). | LoRA recovery source identity | A recovery successor needs a fresh run, output, and tracking identity, but it must not be looked up as if it were the original production-qualified run. Validate the checkpoint's embedded source plan against the accepted production binding, and separately prove that the successor preserves every required scientific, data, model, and topology field. | **Enforced on main:** merge commit [`897842f7`](https://github.com/fleet-ai/cyber-post-train/commit/897842f70334cf958c2ab33bbe0c3c382b278d72), [`training/sft_runtime.py`](../training/sft_runtime.py), and `test_recovery_runtime_reopens_the_embedded_production_source` in [`tests/test_qwen38_lora_first_config_set.py`](../tests/test_qwen38_lora_first_config_set.py). The pre-repair failure is recorded in [`qwen38-lora-recovery-runtime-gate-failure-20260920.json`](evidence/qwen38-lora-recovery-runtime-gate-failure-20260920.json) (receipt SHA-256 `7e736de27805d84dd5620f953fded34a23e2e198fda02f4bee5380c6812a4e87`). This row records code enforcement only; it does not claim that a live recovery run has passed. |
| LoRA recovery seal plan checksum | A saved training plan cannot contain its own checksum. When sealing a resumed checkpoint, calculate the checksum from the exact saved plan, match the terminal and checkpoint records to it, and require one finite metric record for every resumed optimizer step. Do not treat a missing `plan_sha256` field inside the plan as a training failure. | **Enforced on main:** [`training/checkpoints.py`](../training/checkpoints.py), the missing-field and mismatch regressions in [`tests/test_checkpoints.py`](../tests/test_checkpoints.py), and sanitized evidence [`qwen38-lora-recovery-step42-seal-guard-20260921.json`](evidence/qwen38-lora-recovery-step42-seal-guard-20260921.json) (receipt SHA-256 `54af1c695a00063757698af0ee1dea83f39b23298426fdb994fdb03aee9e88a2`). The evidence separates the successful two-step GPU recovery from the later failed CPU seal and does not claim that the step-42 checkpoint is accepted. |
| Checkpoint serving release | A queued evaluator is not proof that a dedicated eight-GPU endpoint is being used. Resume a checkpoint route only for a ready consumer, enforce the no-use deadline, then read the latest Ready state, issue exactly one pause with its resource version, and require terminal `paused`, zero ready replicas, zero active Pods, and exact former-Pod absence. | **Enforced on main:** merge commit [`45887762`](https://github.com/fleet-ai/cyber-post-train/commit/45887762047858fb9a4947911ca5835704951b77), [`training/checkpoint_serving_route.py`](../training/checkpoint_serving_route.py), exact single-pause and terminal-state regressions in [`tests/test_checkpoint_serving_route.py`](../tests/test_checkpoint_serving_route.py), and the teacher/t3k release records in [`qwen38-project-gpu-capacity-reconciliation-20260921.json`](evidence/qwen38-project-gpu-capacity-reconciliation-20260921.json). |
| CPU checkpoint job placement | A CPU-only seal or verifier normally needs a CPU pool and architecture, not one exact hostname. Pinning it to a busy host can leave it waiting even when equivalent CPU nodes are free. Request only the memory the operation needs; if a never-started Pod must be replaced, first record its Pending state, delete its exact UID, prove the output is still absent, and use one fresh name. | **Enforced in the recovered procedure:** terminal evidence [`qwen38-lora-recovery-step42-seal-terminal-20260921.json`](evidence/qwen38-lora-recovery-step42-seal-terminal-20260921.json) (receipt SHA-256 `4dfb8c053ed7afd66c1bbb663b99a30fd5a6f8f8f30ef44a0680c9d22080be07`). The unpinned successor and independent readback both completed with zero GPUs and zero restarts; this is placement guidance, not a claim that every CPU job can run on every node. |
| OCI index versus platform image identity | An OCI index digest and Docker's resolved `linux/amd64` child image ID identify different layers of the same pull. Compare each value to the matching manifest layer; never declare drift by comparing the index directly with the child. | **Enforced on main:** merged anchor [`b4ff90d9`](https://github.com/fleet-ai/cyber-post-train/commit/b4ff90d9b071131ed07dcead6ece9363cf374e82), [`evals/fleet/evaluate.py`](../evals/fleet/evaluate.py), [`tests/test_evaluate.py`](../tests/test_evaluate.py), and sanitized evidence [`qwen38-fresh75-fleet-dev17-failure-v1-20260920.json`](evidence/qwen38-fresh75-fleet-dev17-failure-v1-20260920.json). |
| Docker-in-Docker bind mounts | The evaluator and Docker daemon have separate mount namespaces. Every nested-container bind source must be mounted at the same absolute path in both containers, and a positive startup diagnostic must prove read/write access before model calls. | **Enforced on main:** merged anchor [`b4ff90d9`](https://github.com/fleet-ai/cyber-post-train/commit/b4ff90d9b071131ed07dcead6ece9363cf374e82), shared-path manifests under [`evals/fleet/cluster`](../evals/fleet/cluster), startup enforcement in [`evals/fleet/cluster_entry.py`](../evals/fleet/cluster_entry.py), [`tests/test_fleet_cluster_entry.py`](../tests/test_fleet_cluster_entry.py), and sanitized evidence [`qwen38-fresh75-fleet-dev17-failure-v2-20260920.json`](evidence/qwen38-fresh75-fleet-dev17-failure-v2-20260920.json). |
| Fleet Qwen session model identity | A served Qwen route must be recorded with `session_model: qwen/<exact-served-id>`. An unrecognized provider can produce a completed session whose authoritative `model` is null, so preflight must reject it before any rollout; never infer or alias a missing model after the fact. | **Enforced on main:** guard in [`evals/fleet/evaluate.py`](../evals/fleet/evaluate.py), regression `test_qwen_route_requires_exact_authoritative_session_identity` in [`tests/test_evaluate.py`](../tests/test_evaluate.py), and sanitized evidence [`qwen38-fleet-dev17-session-model-identity-rejection-20260921.json`](evidence/qwen38-fleet-dev17-session-model-identity-rejection-20260921.json). This enforces setup identity; it does not claim that a corrected live evaluation has succeeded. |
| Fleet evaluator bootstrap config binding | The generic ConfigMap key `config.json` is the bootstrap source. It must be byte-identical to the selected `EVAL_CONFIG_NAME` key before any campaign is created; a correct named key alone is not enough. | **Enforced on main:** exact-byte guard in [`run_qwen38_dev17_single_arm_v1.sh`](../evals/fleet/scripts/run_qwen38_dev17_single_arm_v1.sh), its focused assertion in [`tests/test_qwen38_fleet_dev17_eval.py`](../tests/test_qwen38_fleet_dev17_eval.py), and sanitized evidence [`qwen38-self44-fleet-dev17-bootstrap-config-rejection-20260921.json`](evidence/qwen38-self44-fleet-dev17-bootstrap-config-rejection-20260921.json). This enforces setup identity; it does not claim that a corrected live evaluation has succeeded. |
| Fleet evaluator controller slots | Claim an exact ledger cell before checking that cell's serving route. A transient route-check failure before the claim can consume one bounded worker slot without binding a task, leaving an unrelated cell untouched when the controller exits. After claim, quarantine a failed check on that cell and never replay accepted cells. | **Enforced on main:** merge commit [`6ba1042d`](https://github.com/fleet-ai/cyber-post-train/commit/6ba1042dfc0f8f8a64d0ad4d02a21adfd590d91e), per-cell route guard in [`evals/fleet/evaluate.py`](../evals/fleet/evaluate.py), focused regression in [`tests/test_evaluate.py`](../tests/test_evaluate.py), runbook in [`evals/fleet/README.md`](../evals/fleet/README.md), and sanitized evidence [`qwen38-fleet-dev17-base-controller-slot-defect-20260921.json`](evidence/qwen38-fleet-dev17-base-controller-slot-defect-20260921.json). |
| Project GPU capacity count | Count allocated GPU Pods across every namespace and include both training ownership and Fleet inference ownership. Use Kubernetes' effective Pod quantity: regular app containers add together, ordinary init containers contribute their peak because they run sequentially, and restartable init sidecars remain additive. Reconcile each project InferenceModel against its Pods, count an unlabelled project Pod instead of silently dropping it, and include the proposed allocation before a create or resume. A list of current training runs or a naive sum of every container is not a capacity census. | **Repair in review:** [`cyber_post_train/gpu_capacity.py`](../cyber_post_train/gpu_capacity.py), regular-init and restartable-sidecar regressions in [`tests/test_gpu_capacity.py`](../tests/test_gpu_capacity.py), and sanitized release/census evidence in [`qwen38-project-gpu-capacity-reconciliation-20260921.json`](evidence/qwen38-project-gpu-capacity-reconciliation-20260921.json). |

## Additional lessons and repairs in review

Rows marked **Repair in review** are safe historical guidance, but their linked
repair is not a main-branch invariant until it merges and this index is reconciled
again. Rows marked **Enforced on main** name the exact merged anchor.

| Failure boundary | Reusable rule | Exact evidence or repair |
|---|---|---|
| Pinned-image SFT dataset loader | Route the dataset adapter by the exact pinned trainer family. One Qwen full-weight SkyRL image consumes prepared `list[dict]` rows, while the Megatron-LoRA image expects `TextDataset` and `sequence_lengths`. Preflight must invoke the same loader the staged image will use; import success alone is insufficient. | **Enforced on main:** merge commit [`f78dfe93`](https://github.com/fleet-ai/cyber-post-train/commit/f78dfe9346c0f5325d85bb0f8fd97c62ff33c133), plan-family routing in [`training/sft_runtime.py`](../training/sft_runtime.py), exact-image loader preflight in [`training/sft.py`](../training/sft.py), focused regressions in [`tests/test_sft_runtime.py`](../tests/test_sft_runtime.py) and [`tests/test_sft_config.py`](../tests/test_sft_config.py), and sanitized evidence in [`qwen38-next-sft-intentional-launch-20260920.json`](evidence/qwen38-next-sft-intentional-launch-20260920.json). |
| WebExploitBench prompt bundle | A Python benchmark module may depend on sibling prompt files. Seal every sibling as an individually hashed source record, materialize the complete bound set remotely, and reject any launch manifest whose local view differs from that set. Do not include evaluator-only prompt files in exported rollout bundles. | **Enforced on main:** [`benchmark_snapshot.py`](../evals/webexploitbench/tensorlake/benchmark_snapshot.py), [`collection_snapshot_qualification_worker.py`](../evals/webexploitbench/tensorlake/collection_snapshot_qualification_worker.py), [`collection_launcher.py`](../evals/webexploitbench/tensorlake/collection_launcher.py), and their focused tests under [`evals/webexploitbench/tests`](../evals/webexploitbench/tests). Historical acceptance of the zero-model qualification is recorded in the [checkpoint/eval ledger](../configs/evaluation/qwen38-checkpoint-eval-ledger-v1.json); it is an operational gate, not a benchmark result. |
| Serving parity beyond weights | Matching checkpoint weights is necessary but insufficient. A matched comparison must clone and verify the live base image, command, arguments, resources, harness/tool parser, catalog metadata, and content-free tool/logit probes; only model path, exact revision, owned name, lifecycle, and reviewed priority may differ. For a load-balanced base, require exact greedy token identity and finite log probabilities, but record rather than require bit-identical floating-point scores across healthy replicas. | **Enforced on main:** merge commit [`3165af38`](https://github.com/fleet-ai/cyber-post-train/commit/3165af38da301e718acee65d240eee5e9f873b9e), enforcement in [`checkpoint_serving_parity.py`](../training/checkpoint_serving_parity.py), regressions in [`test_checkpoint_serving_parity.py`](../tests/test_checkpoint_serving_parity.py), and sanitized Fresh75/teacher/self-SFT evidence in [`2026-09-20-qwen38-checkpoint-serving-parity.md`](evidence/inference/2026-09-20-qwen38-checkpoint-serving-parity.md). Historical artifact readiness, which does not claim live parity, is in [`qwen38-checkpoint-serving-readiness-v1.json`](../configs/evaluation/qwen38-checkpoint-serving-readiness-v1.json). |
| RL turns with more than one tool call | Preserve every valid call in emitted order, execute in order, record one deterministic result per call, and encode all results as one masked observation group with exactly one next-assistant header. Stop after a successful final submission; malformed calls or results remain invalid episodes and must never receive fabricated reward. | **Repair in review:** exact code commit [`f285ed72`](https://github.com/fleet-ai/cyber-post-train/commit/f285ed72a3047292a39cb02a9da18fec81215f01) with ordered parser, observation, and execution regressions. Sanitized terminal context: [`2026-09-20-skyrl-prod4-direct-rayjob-qualification-v1.md`](https://github.com/fleet-ai/cyber-post-train/blob/2c4e9cd027c3c2d567bb3ad6a91bf2d4bbcfdfc3/docs/evidence/qwen38-study/2026-09-20-skyrl-prod4-direct-rayjob-qualification-v1.md). |
| WebExploitBench serving artifact roles | Do not guess what a live model revision represents or force it to equal a payload hash or export-receipt hash. Bind the observed revision to the exact self-digested route plan and create-once result. Separately verify the checkpoint, export receipt, exported-byte manifest, staged path, runtime, and live parity so every identity keeps one clear meaning. The same checkpoint schema has two known producer-era field sets: validate each exact set, and keep a raw source-plan file hash separate from its canonical JSON hash. | **Enforced on main:** merge commit [`3194eda2`](https://github.com/fleet-ai/cyber-post-train/commit/3194eda274e26f158a6bd70d5a5001b047398e18), [`collection_provenance.py`](../evals/webexploitbench/tensorlake/collection_provenance.py), focused provenance and launcher regressions under [`evals/webexploitbench/tests`](../evals/webexploitbench/tests), and sanitized evidence at [`qwen38-fresh75-wbe-provenance-role-mismatch-20260920.json`](evidence/qwen38-fresh75-wbe-provenance-role-mismatch-20260920.json). |

## Adding a lesson

Add only a proven failure class. Link sanitized evidence, name the deterministic
boundary, and state exactly what the test proves. Put current job IDs, timestamps,
result counts, and digests in the immutable receipt or versioned config—not here.
If a later repair replaces an earlier rule, update the row instead of stacking a
contradictory instruction below it.
