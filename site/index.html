Fleet training data · current catalog checked

A broken task tells us nothing about the model.

We found 1,055 current production security tasks in which the model can use a website but cannot inspect its source code. Only 75 currently meet our strict standard: an earlier attempt proved the exact task ran and scored correctly, the same version is still selected, and the latest review does not mark it as broken.

1,055 current blackbox tasks 75 passed every current check 42 have a fully successful exact attempt 52 currently marked broken 17 promising tasks still need exact proof Fixed split: 50 train · 17 development · 8 final test Scores were not used for selection
Selection rule

A genuine model failure is useful data. A broken website or broken scoring program is not. “Production” and “has an automatic answer check” are not enough on their own.

01

How 1,055 tasks became 75

We required earlier proof from the exact task version, kept only versions that are still selected for production, and removed anything now marked broken.

Worked and scored correctly before+Still current and not known broken=75 tasks

The other 980 tasks are not all broken. Most simply lack the complete, independently checked proof required by this conservative filter.

How the order was chosen

Early runs answer the biggest questions with the fewest GPUs. Later runs tune smaller details or test whether a promising result repeats.

03

How to read the order

These are ranked experiment plans, not claims that the listed settings are already best.

1

Compare the source of learning

First compare strong-teacher attempts, Qwen’s own successes, and a mixture while keeping the exact same task families, each family’s training weight, total training amount, and optimizer settings matched.

2

Find a stable numerical range

Then vary learning rate, batch size, episode group size, and number of passes widely enough to find both under-training and instability.

3

Refine the winning design

Only after a clear winner appears should we tune window extraction, task sampling, reward details, and longer training.

4

Confirm before the final test

Repeat finalists on a second balanced split or random seed. Keep the final Fleet tasks untouched. WebExploitBench is a report-only transfer check: it never selects a recipe, checkpoint, or finalist.

04

Where the suggested ranges came from

These papers and the working Fleet training code give us sensible starting points. They do not prove that a setting will work on long web-security tasks; every row must earn its place on Fleet’s development tasks.
