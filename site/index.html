Research note · 01

Baseline evaluation · Qwen3.8-27B

A broken judge erased real evidence.

We ran the same model on the same 15 public web-security targets with two agent programs. Qwen Code produced a qualified baseline. OpenCode completed the work, but its judge was unavailable, so its recorded score is not a valid model result.

Limits and next test

Fleet data · frozen study roster

A task is useful only when failure means something.

We checked 160 exact blackbox-exploit task versions and kept 89 whose environment, grading, and reproducibility evidence all passed.

160 historical candidates 89 accepted Outcome-blind filtering
Curation principle

A real model failure is valid data. A broken environment or grader is not. The filter never used model scores to choose tasks.

01

The filtering path

Two independent gates were required: proof that the exact task had run correctly, and proof that its current inputs still resolve.

Accepted run evidence∩Complete current bindings=89 tasks

02

What “good” means

Every accepted task version passed both checks below.

1

The run was real

An independently checked receipt showed the exact environment ran, grading finished, the score was a real number, and cleanup completed.

2

The task still reproduces

The current starting data, environment, runtime seed, and grader still resolve to the same fixed identities.

03

How the audit was done

The process was fixed before outcomes were considered.

04

Why 71 versions were excluded

These are evidence gaps, not claims that all 71 tasks are permanently broken.

A separate binding audit found 17 versions without starting-data bindings and 11 without a fixed runtime-seed or grader pin. Those groups overlap with the 62 missing accepted run receipts, so they must not be added together.
